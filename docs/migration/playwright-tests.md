# Матрица переноса Playwright-тестов

Источник: `LabkeeperEditor/src/tests/playwright`.

В исходном наборе найдено 52 активных сценария и 2 сценария, отключенных комментариями. Моки и перехват сетевых запросов в новом наборе не используются. Статус `перенос` означает проверку того же пользовательского результата через production. Статус `условно` означает, что для надежного production-сценария нужны отдельные данные или контролируемое состояние.

Результат переноса: 42 активных исходных сценария входят в основной production-набор, 10 зарегистрированы с явной причиной условного запуска, 2 ранее отключенных сценария сохранены в матрице. Дополнительный smoke-сценарий проверяет чистое открытие анонимного редактора. Отдельный сквозной сценарий проверяет стандартную работу старого пользователя с LaTeX-проектом, файловым менеджером, PDF и SyncTeX. Четыре performance-сценария проверяют отзывчивость редактора при работе с большими документами, множеством сегментов и непрерывным вводом. Отдельная проверка трижды подряд компилирует один и тот же LaTeX-сегмент с новым текстом и каждый раз сверяет текст страницы PDF точным сравнением, поэтому устаревший PDF не может пройти проверку. Лендинговый сценарий проходит путь от примеров на лендинге через вход постоянным тестовым аккаунтом до компиляции склонированного LaTeX-проекта и выполняется только при выставленной `ENABLE_LANDING_TESTS`. Регистрация с чтением реального письма в набор не входит и зарегистрирована как условный сценарий сверх матрицы источника. Всего Playwright обнаруживает 61 логический тест и 366 выполнений в шести браузерных профилях. К четырем настольным профилям добавлены Android Chrome на базе Pixel 7 и iPhone Safari на базе iPhone 15. Вычислительные тесты запускаются в уникальных временных проектах авторизованного E2E-пользователя, чтобы не расходовать общий анонимный лимит.

Два сценария публичной анонимной компиляции из основного набора имеют реальную production-реализацию, но во время запуска динамически переходят в skipped, если сервер возвращает общий лимит HTTP 425. При отсутствии этого ограничения тесты требуют предусмотренные сценарием успешные ответы.

## Проверочный прогон

Последний полный прогон в Docker против production 16 августа 2026 года, когда в профиле обнаруживалось 54 теста и всего было 324 выполнения:

- Настольные профили Microsoft Edge, Google Chrome, Windows Firefox и macOS Safari: 174 passed, 42 skipped, 0 failed.
- Android Chrome: 44 passed, 10 skipped, 0 failed.
- iPhone Safari: 44 passed, 10 skipped, 0 failed.
- Общий результат: 262 passed, 62 skipped, 0 failed.
- После полного прогона: 0 проектов с зарезервированным префиксом.

Состав с тех пор вырос до 61 логического теста в профиле, и на новом составе полный прогон не повторялся, поэтому числа выше относятся к прежнему набору. Критерий приемки пересчитан под новый состав. Явно зарегистрированных условных сценариев теперь 11: десять пропускаются всегда, а `public-project-different-user-compilation-ok` пропускается, пока не заданы `E2E_SECOND_USER_EMAIL` и `E2E_SECOND_USER_PASSWORD`. Лендинговый сценарий дает еще один skipped, когда не выставлена `ENABLE_LANDING_TESTS` или нет `E2E_CAPTCHA_BYPASS_TOKEN`. Отсюда база профиля: 12 skipped и 49 passed без лендинговой переменной, 11 skipped и 50 passed с ней. Сверх базы в skipped динамически уходят выполнения публичной анонимной компиляции, которым сервер ответил общим лимитом HTTP 425, и таких выполнений в профиле бывает от нуля до двух: в проверочном прогоне так перешли два выполнения из двенадцати, остальные прошли. С учетом обеих причин допустимый результат одного браузера составляет от 47 passed и 14 skipped до 50 passed и 11 skipped при отсутствии failed.

## Правила реализации

- В spec-файлах нет `page.locator`, `getByRole`, CSS-селекторов и прямой работы с DOM.
- Все локаторы находятся в `tests/dsl/locators`.
- Все действия и проверки находятся в DSL.
- Переключение мобильных панелей Files, Editor и PDF выполняется через общий DSL-слой.
- PDF-снапшоты включают визуальную проверку страницы и проверку извлеченного текстового слоя для каждого браузерного профиля.
- Подготовка данных работает только с проектами, имя которых начинается с зарезервированного E2E-префикса.
- Спека, которая обращается к лендингу, обязана читать `landingTestsEnabled`, иначе `npm run check:architecture` сообщает о нарушении.
- Сетевые ответы не подменяются, не прерываются и не модифицируются.
- Проверяется итоговое состояние production, а не только факт отправки запроса.
